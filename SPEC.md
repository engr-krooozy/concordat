## Objective

**Problem.** Fraud rings deliberately exploit the seams between financial institutions: the same
mule network hits five banks, each bank sees one disconnected fragment, and privacy law (GDPR,
NDPR, bank secrecy) forbids them from pooling raw customer data. Existing consortium approaches
(UK COSMIC, Verafin) centralize everything into one provider — the exact thing privacy and legal
teams resist. Result: cross-institution rings are systematically under-detected.

**Solution.** Each bank operates a sovereign agent fleet inside its own perimeter. When a bank's
trace dies at its boundary, its fleet:

1. **Discovers** counterpart fleets at other banks via A2A agent cards (a registry = agent catalog).
2. **Negotiates** the terms of a joint investigation — which computations, what aggregation
   thresholds (k-anonymity), hashed identifiers only, TTL — each proposal checked by both sides'
   policy engines against machine-readable data-sharing policies.
3. **Compiles** the agreed "concordat" into an ephemeral BigQuery clean room (Analytics Hub
   data clean rooms; authorized-views fallback) and runs the joint money-flow query.
4. **Acts** only inside its own walls — flags/freezes its own accounts — behind human approval
   gates, and files a SAR-style report per bank.
5. **Dissolves** the room. What persists: the signed concordat document, the audit trail, and
   each bank's own case file.

Everything runs **asynchronously**: Pub/Sub-driven, long-running cases with state in Firestore.
No chat window is the product — a mission-control view observes fleets working in the background.

**Users.** Financial-crime / AML teams at banks and fintechs; the demo persona is a fraud analyst
at each of three banks who only sees approval requests and final case files.

**Success looks like:** a judge watches three banks each fail alone, then watches the fleets
negotiate on screen and the full ring materialize in the clean room — and immediately understands
why "data diplomacy" is a new category.

## Code Style

```python
# agents/diplomat.py
class NegotiationProposal(BaseModel):
    """One round of the concordat negotiation. Immutable; every round is audit-logged."""

    case_id: str
    computations: list[JointComputation]  # e.g. path-join on hashed account ids
    k_threshold: int  # min group size in any released aggregate
    identifier_scheme: Literal["sha256_salted"]
    ttl_hours: int
    round: int


async def propose_terms(case: CaseState, policy: BankPolicy) -> NegotiationProposal:
    """Draft the narrowest proposal that could still resolve the trace dead-end.

    Gemini drafts; the policy engine has final say — a proposal that violates
    local policy is never sent, regardless of model output.
    """
```

Conventions: type-hinted Python, Pydantic models for every cross-boundary message, `ruff` for
lint/format, agents small and single-purpose, **deterministic guardrails wrap probabilistic
models** (the policy engine is code, not a prompt). No secrets in code — env/Secret Manager only.

## Testing Strategy

- `pytest` unit tests for: policy evaluator (the compliance core — highest coverage), negotiation
  state machine (propose→counter→accept/reject paths), hash/redaction functions, joint-query
  builder (golden SQL snapshots).
- **Contract tests** for A2A messages: every message type round-trips through Pydantic schemas.
- One **end-to-end golden path** test against the seeded dataset (can run against BQ emulator-less,
  tagged `@integration`, run pre-deploy).
- LLM outputs are never asserted verbatim; assert on validated structure and policy-engine verdicts.
- Coverage target: policy + negotiation modules ≥ 90%; elsewhere pragmatic (hackathon).

## Boundaries

  behind the policy engine + redactor; audit-log every negotiation round and clean-room action;
